# 14. Operating System and Administration Basics

[[00 - Overview|← Overview]]

**Related Security+ material:** [[4.5 - Operating System Security]] · [[4.1 - Secure Baselines]] · [[4.1 - Hardening Targets]]

| Term | Simple Explanation | Example | Security+ Why It Matters |
|---|---|---|---|
| **User account** | An identity used by a person or service to access a system. | brian.rawlins logs into Windows. | Accounts require proper permissions and protection. |
| **Administrator account** | An account with broad authority to change a system. | Installing software or creating users. | Attackers seek administrative privileges. |
| **Standard user** | An account with limited rights for normal work. | A user can run applications but not change system-wide settings. | Limited rights reduce damage from mistakes and malware. |
| **Root** | The highest-privileged account on Linux and Unix systems. | Root can modify any file. | Compromising root gives an attacker full control. |
| **Privilege** | Authority to perform a protected action. | Installing drivers or reading restricted files. | Security teams minimize unnecessary privileges. |
| **Permission** | A rule specifying who may access a resource and what they may do. | A user may read but not edit a file. | Weak permissions expose data and systems. |
| **File system** | The structure an operating system uses to organize files and folders. | NTFS on Windows or ext4 on Linux. | File systems support permissions, encryption, and auditing. |
| **File extension** | Characters after a filename that often identify the file type. | .exe, .pdf, or .docx. | Attackers disguise malicious files with misleading extensions. |
| **Executable file** | A file containing instructions the computer can run. | .exe or a Linux binary. | Malicious executables install or launch malware. |
| [[2.3 - Cross-site Scripting\|Script]] | A text-based set of commands interpreted by another program. | PowerShell, Bash, Python, or JavaScript. | Attackers use scripts for automation and fileless attacks. |
| **Command line** | A text interface used to control a computer by typing commands. | PowerShell or Linux Bash. | Administrators and attackers both use command-line tools. |
| **GUI** | A visual interface using windows, icons, and menus. | Windows desktop. | Some security tools provide GUI and command-line interfaces. |
| **Registry** | A Windows database containing system and application settings. | Startup settings stored in registry keys. | Malware may use registry entries for persistence. |
| **Environment variable** | A named value programs use to find settings or locations. | PATH tells the system where to search for commands. | Attackers may alter variables to execute malicious software. |
| **Patch** | An update that fixes defects or vulnerabilities. | Installing a Windows security update. | Unpatched systems remain vulnerable to known exploits. |
| **Hotfix** | A focused update that addresses a specific urgent problem. | Fixing one actively exploited vulnerability. | Organizations may deploy hotfixes outside normal update cycles. |
| **Service pack** | A larger collection of updates released together. | An older Windows service pack. | Service packs bring systems to a known patch level. |
| **End of life** | The point when a vendor stops supporting a product. | An operating system no longer receives security updates. | Unsupported products accumulate unpatched vulnerabilities. |
| [[2.5 - Hardening Techniques\|Hardening]] | Changing settings to reduce unnecessary exposure and strengthen security. | Disable unused services and enforce strong passwords. | Hardening reduces the attack surface. |
| **Baseline configuration** | An approved standard set of secure settings. | Every workstation uses the same firewall and audit settings. | Baselines make security consistent and measurable. |
| **Image** | A prepared copy of an operating system and its settings used to deploy systems. | A standard Windows workstation image. | Secure images prevent misconfiguration during deployment. |
| [[3.4 - Backups\|Backup]] | A separate copy of data used for recovery. | Nightly copies stored on another system. | Backups help recover from ransomware and failure. |
| **Snapshot** | A point-in-time record of a system or virtual machine state. | Taking a VM snapshot before installing an update. | Snapshots support quick rollback but do not replace backups. |
| **Log** | A record of events generated by a system or application. | Windows records failed login attempts. | Logs support monitoring, detection, and investigation. |
| **Audit trail** | A chronological record showing who performed actions and when. | A log records that an admin deleted an account. | Audit trails establish accountability. |
